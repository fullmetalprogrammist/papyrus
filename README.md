#  Что это

- Некоторые мои md-заметки, конвертированные в html.
- Как по задумке это должно выглядеть:
  - На главной странице собраны ссылки на статьи. Никакого автоматизма, все руками пишется для максимальной свободы оформления. Физическая структура папок и файлов т.о. отделена от логической группировки.
  - Статья - это отдельная тема с кучей подразделов, раскрывающих эту тему. По задумке, оформление темы единым файлом должно позволить лучше выстроить связи между элементами. Не нужно лазить по множеству файлов, все в одном месте. Примерно как небольшая книга.
    - Заголовков трех уровней (ну может быть четырех максимум) должно хватить, чтобы выстроить оптимальную схему.
  - Для удобства перемещения по огромным простыням я добавил скрипт, который автоматически собирает по заголовкам оглавление и оформляет в виде collapse \ expand списка ссылок.



# Как пользоваться

## 1. Конвертировать md в html

- Чтобы все работало, в системе должен быть установлен pandoc и node.js
- Для конвертации используется скрипт `papyrus.js` в корне проекта:

```
node papyrus.js
```

- Доступные ключи:
  - Без ключей - скрипт рекурсивно ищет в папке content все md файлы и каждый конвертирует в index.html.
  - `--keep-name` - если не указан, файл конвертируется в index.html. Если указан, то берется имя исходного файла.
  - `--today` - скрипт конвертирует только те md, которые были отредактированы сегодня.
  - `--ago -m 10` или `--ago -d 3` - конвертировать md, которые редактировались, соответственно, в течение последних 10 минут или последних трех дней.
  - `-i "D:\путь\до\файла.md"` - скрипт конвертирует только указанный файл. Путь абсолютный.
    - `-i "D:\путь\до\"` - можно указать просто директорию. Если в ней только один md, он сконвертируется в index.html или оригинальноеимя.html в зависимости от --keep-name. Если в директории несколько md, все они сконвертируются под своими оригинальными именами.
- Сконвертированный файл оказывается рядом с оригинальным.
- Файлы и папки начинающиеся с `_` игнорируются, поэтому можно удобно держать в одной директории и те материалы, которые хочешь сделать веб-страницами, и те, которые должны просто остаться обычными md.
  - Просто положить их например в папку `_notes` в тематической папке, например `doker\_notes`
  - Если почему-то хочется _папку сконвертировать, можно ее явно указать через ключ `-i`



## 2. Добавить ссылку на главную

- Добавить в `index.html` ссылку на статью.
  - Ссылка должна выглядеть вот так, с завершающим слэшем:

```html
<a href="/papyrus/content/java/threads/">Многопоточность</a>
```

- За счет того что файлы называются index.html, не приходится указывать в ссылке имя самого файла.
- Главное не забыть слэш в конце! Иначе не будут грузиться картинки, потому что последняя часть path исчезнет из url.



## 3. Смотреть на локальном сервере

- Запустить

```
node server.js -b papyrus
```

- Открыть страницу

```
 http://localhost:3000/papyrus/
```



# Как это все устроено

- `/pandoc stuff`
  - `fmp.theme` - "тема" для оформления исходного кода.
    - Обычный json, можно нейросеткой сгенерировать любой внешний вид по вкусу.
  - `fmptemplate.html` - шаблон, в который пандок вставляет контент из md.
    - Обычный шаблон пандока, но в него внедрены
      - кнопка "Наверх" и "Домой"
      - css-стили для статьи \ оглавления \ всего остального
      - скрипт фолда \ анфолда исходного кода
      - скрипт, формирующий оглавление из заголовков
    - В случае если надо приделать новые скрипты, их надо сложить в папку `/scripts` и явно вписать в этот шаблон. Аналогично со стилями - класть в папку `/styles` и приделывать в шаблоне. Добавлять в это место:

```html
<!-- ============= ============= Мои стили и скрипты ============= ============= -->
<!-- Должны подключать тут, чтобы перекрыть дефолты пандока -->
<link rel="stylesheet" href="/papyrus/styles/article-page.css">
<script src="/papyrus/scripts/oglavlenie.js" defer></script>
<script src="/papyrus/scripts/source-code-expand-collapse.js" defer></script>
<!-- ============= ============= =================== ============= ============= -->
```

- `/styles`
  - `article-page.css` - стили для статьи. Здесь собраны все стили - для текста, кнопок, меню оглавления и все остальное, все что есть на странице статьи.
  - `main-page.css` - стили для главной страницы, на которой собраны ссылки на все статьи.
- `papyrus.js` - скрипт для конвертации md в html. Использует pandoc.
- `server.js` - самописный мини-веб-сервер, чтобы не зависеть от vs code плагинов, плюс он имитирует работу с путями как на github pages.
- `/content` - сюда надо складывать md-конспекты, чтобы скрипт мог их найти.



# Проблемы

## Пути github pages vs локальные пути

- Для github pages рут это `https://fullmetalprogrammist.github.io/` но все ссылки дополняются названием репозитория `papyrus`.
  - Поэтому для ghp ссылки надо оформлять как `/papyrus` для статей, стилей, скриптов и т.д.
  - Но локально на компьютере это вызывает проблемы, потому что рутом будет просто папка, из которой запускаешь сервер, например через расширение live server для vs code, безо всяких /papyrus.
  - Так что я сгенерировал мини-веб-сервер, чтобы эту проблему обойти. Он находится в корне, файл `server.js` и запускается вот так:

```
node server.js -b papyrus
```

- Тогда локально пути можно будет писать так как же как и для ghp.
- Есть live reload.
- Страница будет доступна по адресу:

```
 http://localhost:3000/papyrus/
```
